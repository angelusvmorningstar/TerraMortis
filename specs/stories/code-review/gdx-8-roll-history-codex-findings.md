### [Pass 2] Every real roller branch generates a schema-invalid POST

- **Severity**: High
- **File:line**: `public/js/suite/roll-v2.js:932-938,1010-1016,1047-1053`; `public/js/shared/dice.js:8-25`; `server/schemas/roll_log.schema.js:25-27`
- **Triggering input or sequence**: A player makes any roll while `game_in_progress` is true. All three call sites pass numeric `state.AGAIN` as `again_rule`, while the schema accepts only string/null. Standard and contested rolls additionally pass `wC`, an array of dice-chain objects shaped like `{ r: { v, s, x }, ch: [...] }`, while the schema requires each `results` item to be an integer from 1 through 10. - **Observable consequence**: The server returns 400 for every POST generated by `doRoll()`. `_logRoll()` swallows that rejection, so no player roll is persisted and no live WS event is emitted; the feature appears merely empty rather than visibly broken.
- **Confidence**: Very high; confirmed by tracing the real dice return type and by runtime validation with the installed Ajv configuration.
